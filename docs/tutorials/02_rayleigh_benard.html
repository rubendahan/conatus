A first initial-value problem: Rayleigh–Bénard 2D, CPU then GPU¶

Goal. Write the Boussinesq equations once, time-step them on the CPU, check that a small perturbation grows at the rate predicted by the eigenvalue problem of the same equations, then run the same plan on a GPU. Expected. Growth rate \(\sigma = 5.5425059\) of the \(k = \pi\) roll at \(Ra = 2500\), \(Pr = 1\) (EVP of the same equations; the streamfunction formulation gives the same value); onset is at \(Ra_c = 1707.762\) (Reid & Harris 1958). CPU and GPU agree to rounding (\(\le 10^{-11}\) relative). Time: about 10 s of CPU (2a); about a minute on one GPU, mostly start-up (2b). Scripts: t02a_rayleigh_benard_cpu.py, t02b_rayleigh_benard_gpu.py

The equations¶

In thermal-diffusion units, \(z \in [-1/2, 1/2]\), rigid isothermal walls:

\[ \partial_t \mathbf{u} - Pr\,\nabla^2 \mathbf{u} + \nabla p - Pr\,Ra\,T\,\mathbf{e}_z = -\mathbf{u}\cdot\nabla\mathbf{u},\qquad \partial_t T - \nabla^2 T = -\mathbf{u}\cdot\nabla T,\qquad \nabla\cdot\mathbf{u} = 0, \]

with \(T = \pm 1/2\) and \(\mathbf{u} = 0\) on the walls. They are typed as written: terms may sit on either side; the linear ones become implicit, the nonlinear ones explicit, and explain() lists the split (override with implicit(...) / explicit(...)).

Write the problem¶

import numpy as np

import conatus as cn

box = cn.Box(x=cn.periodic(2.0), z=cn.walls(-0.5, 0.5))   # one roll pair: k = 2 pi / 2 = pi
m = cn.Model(box, name="Rayleigh-Benard 2D", Ra=2500, Pr=1)
u, p, T = m.velocity("u"), m.pressure("p"), m.scalar("T")
m.equations("""
    momentum:   dt(u) + grad(p) - Pr*lap(u) = Pr*Ra*T*ez - u·grad(u)
    continuity: div(u) = 0
    heat:       dt(T) - lap(T) = -u·grad(T)
""")
m.at("bottom", u=0, T=+0.5)                  # hot bottom, no slip
m.at("top", u=0, T=-0.5)                     # cold top, no slip
print(m.explain())                           # split, taus, pressure gauge, dealiasing

  • The geometry names its boundaries (bottom, top); conditions are given there by unknown. m.explain() shows the bases and tau terms selected by the native compiler: two taus per second-order equation (modes \(N_z-1\), \(N_z-2\) of the equation where the unknown has its highest \(z\)-order), the pressure gauge tau_p with integ(p) = 0 and the divergence tau dot(ez, lift(tau_u2, z, -1)), recognized from the structure (\(p\) only under grad, div(u) = 0 without time derivative), and the declared default dealiasing 3/2.

  • The discrete matrices and right-hand sides are bit-identical to the hand-written IR version (expert/t02a_rayleigh_benard_cpu.py), up to the order of the unknowns.

The eigenvalue problem of the same equations¶

lin = m.linearize(about={u: 0, T: lambda z: -z})          # conduction state T0 = -z
modes = lin.eigenvalues(N=24, k=np.pi)                     # 24 Chebyshev modes, wavenumber pi
sigma_evp = modes.values.real.max()
print(lin.explain())
print(f"EVP: growth rate of the k = pi roll at Ra = 2500: sigma = {sigma_evp:.10f}")

m.linearize(about=...) takes the Fréchet derivative of the same model around the conduction state \(T_0 = -z\) and turns \(\partial_t\) into the eigenvalue \(s\). The perturbation equations come from this model and the supplied base state. eigenvalues(N=24, k=np.pi) gives 24 Chebyshev modes in \(z\) and the smallest Fourier size holding \(k = \pi\) (declared: the matrices of one wavenumber do not depend on the others).

Time-step, with the error and the CFL kept apart¶

sim = m.simulate(N=(16, 24), scheme="RK443", dt=5e-4)   # resolution, scheme, dt: explicit
sim.initial(T=lambda x, z: -z + 1e-6 * np.cos(np.pi * x) * np.cos(np.pi * z))
print(sim.explain())


def roll_amplitude(sim):
    """Max over the grid of T minus its horizontal mean (the conduction profile -z drops out)."""
    Tg = sim.grid("T")
    return np.abs(Tg - Tg.mean(axis=0)).max()


sim.run(until=0.3)                           # faster-decaying modes are gone
a1, t1 = roll_amplitude(sim), sim.t
sim.run(until=0.8)
print(f"CFL time step at safety 0.5: {sim.cfl('u', 0.5):.2e}  (a stability indicator, not an error)")

  • m.simulate(N=(16, 24), scheme="RK443", dt=5e-4): resolution, scheme and step are explicit. The schemes (SBDF1–4, CNAB, RK111/222/443, …) are listed in Simulations and time steppers. run(until=0.8) needs a stop time that is a whole number of steps from the current time.

  • sim.cfl("u", 0.5) is a stability indicator built from the velocity. The temporal error estimate (EmbeddedError(sim.solver)) and everything else of the expert IVPSolver stay available through sim.solver.

  • sim.explain() shows the automatic decisions, then the systems (one per Fourier wavenumber), their bands and how they are solved.

Measure the growth rate, and write the Methods paragraph¶

a2, t2 = roll_amplitude(sim), sim.t
sigma_ivp = np.log(a2 / a1) / (t2 - t1)
print(f"IVP: measured growth rate sigma = {sigma_ivp:.10f} over t in [{t1:.2f}, {t2:.2f}]")
print(sim.methods().explain())               # the "Methods" paragraph for a paper

sim.methods() writes the “Numerical methods” paragraph of a paper from the plan itself (bases, sizes, tau method, dealiasing, scheme, step), with the citations it relies on, and states what the native layer decided.

A run over several jobs¶

A cluster job has a time limit, so a long run is a chain of jobs, and each job runs the same script. sim.resume_or_start(directory, T=...) continues from the latest checkpoint of directory when there is one and starts from the initial state otherwise; checkpoints writes bit-for-bit restart files; output writes the fields and numbers you ask for. Without mode=, the output file is created on a fresh start and continued after a restart. On a fresh start an existing file is refused; give mode="w" to replace it. After a restart, rows written after the checkpoint are dropped and written again by the restarted run.

import tempfile
from pathlib import Path

work = Path(tempfile.mkdtemp(prefix="rb_chain_"))   # a real run: a directory of your project space


def job(until):
    """The script of every job of a chain: the same lines for the first job and the next ones."""
    sim = m.simulate(N=(16, 24), scheme="RK443", dt=5e-4)
    # the latest checkpoint of chk/ if there is one, else this initial state at t = 0
    sim.resume_or_start(work / "chk",
                        T=lambda x, z: -z + 1e-6 * np.cos(np.pi * x) * np.cos(np.pi * z))
    sim.checkpoints(work / "chk", every=200, keep=2)          # exact restart files
    sim.output(work / "rb.h5", every=100,                     # no mode=: follows the branch
               tasks={"T": "T", "KE": lambda s: s.evaluate("integ(u@u)/2")})
    sim.run(until=until)
    return sim


job(0.3)                                     # first job: from t = 0, stopped at t = 0.3
chain = job(0.8)                             # next job: from the checkpoint of t = 0.3
print("\n".join(s for s in chain.explain().splitlines() if "resume_or_start" in s))
d = cn.io.read(work / "rb.h5")               # also readable with h5py alone
print(f"{len(d.sim_time)} rows, t = {d.sim_time[0]:.2f} ... {d.sim_time[-1]:.2f}, "
      f"kinetic energy at the end {d.tasks['KE'][-1]:.3e}")

explain() says which branch was taken and which mode each file got. The chain gives the state of the uninterrupted run above bit for bit (checked below), because a checkpoint holds the state, the scheme’s history and the clock. More in Input and output (what an analysis file holds, mode=, the formats).

Check. EVP: \(\sigma = 5.5425059231\) (the streamfunction formulation gives \(5.542505923\)); IVP from a \(10^{-6}\) perturbation: \(\sigma = 5.5425080\) over \(t \in [0.3, 0.8]\), i.e. \(4\times10^{-7}\) relative.

SIGMA = 5.5425059                            # EVP of the same equations (tests/ivp/test_psi_theta.py)
assert abs(sigma_evp - SIGMA) < 1e-6, sigma_evp
assert abs(sigma_ivp - sigma_evp) < 1e-5, (sigma_ivp, sigma_evp)
assert np.array_equal(chain.solver.X, sim.solver.X) and len(d.sim_time) == 17   # two jobs = one run (t = 0 row included)
print("OK: the IVP grows at the EVP rate; the EVP matches the psi-theta formulation; the two-job "
      "chain is the uninterrupted run bit for bit")

Methods paragraph generated from the plan (edit before publishing):

The IVP 'Rayleigh-Benard 2D' for (u, p, T) was solved with Conatus. The domain is discretized as follows: x ∈ [0, 2) is periodic and expanded in a real (cosine/sine) Fourier series of 16 modes; z ∈ [-0.5, 0.5] is expanded in 24 Chebyshev polynomials of the first kind. Derivatives, basis conversions and multiplications by non-constant coefficients use the sparse, banded ultraspherical operators of Olver & Townsend, and boundary conditions are imposed with the generalized tau method (4 tau variable(s), each entering through a lift polynomial), following Burns et al. The Fourier directions decouple, giving 8 independent systems, one per wavenumber. Nonlinear terms are evaluated pseudospectrally with dealiasing factors 3/2 in x, 3/2 in z. The structural rank of every system was checked before factorization. Time integration uses the third-order, four-stage IMEX Runge–Kutta scheme (4,4,3) of Ascher, Ruuth & Spiteri, whose implicit diagonal is constant so that a single factorization serves all stages, with a constant step Δt = 0.0005. The implicit systems are solved by banded LU factorization with a low-rank (Woodbury) correction for the tau rows, batched over wavenumbers on CPU, in float64 arithmetic. The equations were declared in the native layer of Conatus as written on paper; the implicit-explicit split, the 4 tau term(s) (each in the equation where its unknown has its highest wall-normal order) and the pressure gauge and its integral constraint were placed by fixed, declared rules (listed by explain()). The dealiasing factor 3/2 is the declared default of the native layer ((p+1)/2 for the highest polynomial degree p = 2 of the equations in the unknowns and given fields, at least 3/2).

The same run on a GPU¶

The model does not change. Only the backend is chosen, explicitly: backend="cuda" in m.simulate(...) moves the state, the batched banded solves and the transforms to the device; f_backend="fused" evaluates the nonlinear terms with fused kernels (the NumPy "evaluator" remains the oracle). sim.solver.run_graph(n) captures one step as a CUDA graph and replays it, which removes the launch latency.

The GPU script starts from the same model, at \(Ra = 10^5\). Its last three blocks need a CUDA device.

import time

import numpy as np

import conatus as cn

def rayleigh_benard(Ra):
    """The model of tutorial 2a (same equations, same conditions), at Rayleigh number Ra."""
    m = cn.Model(cn.Box(x=cn.periodic(2.0), z=cn.walls(-0.5, 0.5)), name="Rayleigh-Benard 2D",
                 Ra=Ra, Pr=1)
    m.velocity("u")
    m.pressure("p")
    m.scalar("T")
    m.equations("""
        momentum:   dt(u) + grad(p) - Pr*lap(u) = Pr*Ra*T*ez - u·grad(u)
        continuity: div(u) = 0
        heat:       dt(T) - lap(T) = -u·grad(T)
    """)
    m.at("bottom", u=0, T=+0.5)
    m.at("top", u=0, T=-0.5)
    return m


m = rayleigh_benard(Ra=1e5)
T_init = lambda x, z: -z + 1e-2 * np.cos(np.pi * x) * np.cos(np.pi * z)  # noqa: E731

# requires: gpu
runs, early = {}, {}
for label, kw in [("cpu", dict(backend="cpu")),
                  ("gpu", dict(backend="cuda", f_backend="fused"))]:   # both choices explicit
    s = m.simulate(N=(128, 64), scheme="RK443", dt=2e-4, **kw)
    s.initial(T=T_init)
    s.run(steps=20)                                  # compare here: rounding not yet amplified
    early[label] = s.grid("T").copy()
    t0 = time.perf_counter()
    s.run(steps=180)                                 # timing (the flow becomes strongly nonlinear)
    runs[label] = (s, (time.perf_counter() - t0) / 180)
    print(f"{label}: {1e3 * runs[label][1]:.2f} ms per step")
print(runs["gpu"][0].explain())

# requires: gpu
g = m.simulate(N=(128, 64), scheme="RK443", dt=2e-4, backend="cuda", f_backend="fused")
g.initial(T=T_init)
g.solver.run_graph(20)                               # expert: capture one step, replay it
graph_early = g.grid("T").copy()
t0 = time.perf_counter()
g.solver.run_graph(180)
print(f"gpu + CUDA graph: {1e3 * (time.perf_counter() - t0) / 180:.2f} ms per step")

# requires: gpu
Tc, Tg = early["cpu"], early["gpu"]
diff_gpu = np.abs(Tc - Tg).max() / np.abs(Tc).max()
diff_graph = np.abs(graph_early - Tg).max() / np.abs(Tg).max()
late = np.abs(runs["cpu"][0].grid("T") - runs["gpu"][0].grid("T")).max()
print(f"after 20 steps: relative max |T_cpu - T_gpu| = {diff_gpu:.1e}; graph vs plain = {diff_graph:.1e}")
print(f"after 200 steps: max |T_cpu - T_gpu| = {late:.1e} (rounding amplified by the instability)")
assert diff_gpu <= 1e-11 and diff_graph <= 1e-13
print("OK: CPU and GPU agree to rounding; the graph replay is the same computation")

CPU and GPU are not bitwise equal (different summation orders), so the check is agreement to rounding, the cross-backend model of the test suite, and it is made early (20 steps). At \(Ra = 10^5\) the conduction state is violently unstable: the linearized problem has growth rates up to \(\sigma \approx 225\) (wavenumber \(2\pi\)), and the flow saturates nonlinearly within the 200 steps. Any rounding difference is amplified with it: after 200 steps two CPU evaluations of the same nonlinear terms (NumPy evaluator vs fused kernels) differ by \(4\times10^{-6}\), as do CPU and GPU. Comparing trajectories of an unstable flow needs a time horizon, stated with the tolerance.

Check. After 20 steps CPU and GPU (fused kernels) agree to \(1.0\times10^{-14}\) relative; the CUDA-graph replay equals plain GPU steps exactly.
