For AI agents¶

What an AI coding agent reads before using Conatus, and the JSON interface it uses while it works.

An agent that writes and runs Conatus code should be given one page, AGENTS.md, at the root of the repository. It lists the usable surface, one call per line, grouped by task. It also gives rules against common agent mistakes: read a refusal and its suggested fix, write each tolerance that decides digits, check residuals, convergence and explain(), and check cost and memory before a large run. The test suite checks the page against the library: the names it cites exist, the major public elements are listed, and its example runs.

Ask the library, in JSON¶

Three commands answer an agent without any prose to parse. Each prints one JSON object (keys sorted, "api": 1; within an API version fields are only added) and says what happened by its exit code.

python -m conatus agent                          # versions, CPU/GPU, the user layer, watched runs
python -m conatus agent explain cn.Model.simulate     # signature, required arguments and tolerances
                                                      # (and "deprecated": former argument names)
python -m conatus agent explain cn.problems.native.rayleigh_benard   # a ready model: its unknowns too
python -m conatus agent check run.py             # dry run of a script: what Conatus would refuse

check runs the script for real up to its first expensive call (a time integration, an eigenvalue solve, a Newton search, a continuation…) and stops there. On the way, simulate builds its solver, so a search that takes sim.solver is reached too; calls that write files or announce a Studio run (watch, output, checkpoints, save) are skipped. At the stop, the call’s arguments are checked against its signature, the model is discretised at the requested resolution (so an under-resolved coefficient or a missing boundary condition is refused here, with its fix), and the explain() texts are collected. With backend="cuda", simulate itself is the stop (no device memory is allocated) and the device memory of the simulation is predicted; --memory does the same prediction for a CPU simulation. No intercepted call integrates or solves (the list is conatus.agent.EXPENSIVE).

The argument values of the stopped call are checked only where the call has a separate check that does nothing else: Simulation.run and IVPSolver.run (a negative or fractional number of steps, an end time before the clock, a callback without every). For any other stop, a value the call would refuse (a negative tolerance, a bracket in the wrong order) is found only when the script runs. The validated field of the report says, for the stop, which of the two applied, and ok means that nothing was refused among the checks that ran.

check is not a sandbox. The script runs in the current process with your privileges: its own code (writing a file, starting a subprocess) runs as written, and only the Conatus calls of that list are intercepted, in that process only (not in a child process or an MPI launch). A script that catches the stop (a bare except: or except BaseException) and goes on is reported as an error, since the lines after it ran for real. The timeout cannot interrupt a long call inside compiled code. Check only scripts you would run yourself.

AGENTS.md¶

The start of the page, as an agent reads it: installation, the mental model, a working example, the surface by task and the rules. The rest of AGENTS.md covers live runs (Pilot a run from a script or an agent) and the JSON contract described above.

Conatus: spectral PDEs and dynamical systems on CPU and GPU (0.2; the API is young, see the deprecation notes below). You write equations as on paper; Conatus discretises (Fourier/Chebyshev/curvilinear bases, taus placed for you), integrates, solves eigenproblems and finds structure (orbits, bifurcations, Floquet, optimal perturbations). Declare numerical choices explicitly. When a call lacks one, Conatus raises an error that says what to write. A few older inferences remain (the growth convention of an eigenvalue) and emit a DefaultChoiceWarning.

1. Install, verify, orient (machine-readable)¶

pip install ".[tutorials]"             # or installed (Python 3.11-3.13; h5py + matplotlib); writes only under ~/.cache/conatus
python -m conatus doctor --json        # what this machine can run; exit 1 if something required is missing
python -m conatus agent                # JSON: versions, CPU/GPU, user-layer names, watched runs
python -m conatus agent explain cn.Model.simulate     # signature, required args, required tolerances (+ unknowns of a ready model)
python -m conatus agent check run.py   # dry run (no solve): refusals + fix, missing tolerances, memory

2. Mental model¶

  • import conatus as cn: native layer. Geometry → cn.Model (unknowns, parameters, equations as text, conditions by boundary name) → numerics given at the call (N, scheme, dt, backend) → result object with .explain().

  • import conatus.expert as X: expert layer (IR: bases, fields, X.IVP/X.EVP/…, X.discretize → X.Plan, X.IVPSolver). Every model compiles to it: m.compile(N).problem, sim.solver, sim.plan. A name present in both layers has one meaning.

  • One word per notion: steps (number of time steps), k (a wavenumber keyword; a problem parameter keeps its literature name, e.g. alpha of Orr–Sommerfeld), eta (radius ratio), n_modes, max_iterations, tol (exceptions until 0.3: the fields ContinuationSettings(tolerance=, max_newton=), also read as cfg.tol, cfg.max_iterations); former names warn (conatus._deprecation.RENAMES).

  • Names below: m = cn.Model, sim = cn.model.Simulation, lin = cn.model.Linearization, X = conatus.expert.

3. Minimal working example (executed by the test suite)¶

import numpy as np
import conatus as cn

m = cn.Model(cn.Box(x=cn.periodic(22.0)), name="Kuramoto-Sivashinsky")
m.scalar("u")
m.equations("dt(u) + lap(u) + lap(lap(u)) = -u*dx(u)")
sim = m.simulate(N=32, scheme="RK443", dt=0.01)        # N, scheme and dt are required
sim.initial(u=lambda x: np.cos(2 * np.pi * x / 22.0))
sim.run(steps=20)                                     # run(until=T) must land on a whole step
print(sim.explain())                                  # short summary; full=True adds compiler decisions

os_ = cn.Model(cn.Box(y=cn.walls(-1, 1)), name="Orr-Sommerfeld", Re=1e4, alpha=1.0)
os_.scalar("v")
os_.given(U=lambda y: 1 - y**2)
os_.eigenvalue("c", growth="imag")
os_.define("L2(f) = dy(dy(f)) - alpha**2*f")
os_.equations("L2(L2(v))/(1j*alpha*Re) - U*L2(v) + dy(dy(U))*v + c*L2(v) = 0")
os_.at("walls", "v = 0", "dy(v) = 0")
res = os_.eigenvalues(N=64, drift=96, drift_tol=1e-6)  # drift test removes modes that move with N
i = int(res.order()[0])                               # least stable first (growth = Im c)
assert res.residuals[i] < 1e-12                       # check the residual (then convergence in N)

Critical point of a ready linearization, and its mode (Rayleigh–Bénard, no-slip walls):

import numpy as np
import conatus as cn
import conatus.expert as X

lin = cn.problems.native.rayleigh_benard_evp(k=3.1, Ra=1708.0, Pr=1.0)
P = lin.parametric(24, over=("Ra", "k"), drift=32, drift_tol=1e-6)   # k: the wavenumber
crit = X.critical(P, "Ra", bracket=(1500.0, 2000.0), over={"k": (2.5, 3.8)}, xtol=1e-9)
assert abs(crit.value - 1707.762) < 1e-3 and abs(crit.over["k"] - 3.1163) < 1e-3
kc = crit.over["k"]
res = cn.problems.native.rayleigh_benard_evp(k=kc, Ra=crit.value, Pr=1.0).eigenvalues(
    24, k=kc, drift=32, drift_tol=1e-6)
md = res.mode(int(res.order()[0]))
T = md.at("T", z=np.linspace(-0.5, 0.5, 101))[0]     # walls included; row x = 0

5. Rules that prevent agent mistakes¶

  1. Errors carry a fix. A refusal is a cn.errors.ConatusError with .message, .where, .why, .fix, .doc. Read fix, apply it yourself only if it is what you mean. Let numerical refusals propagate; if a script handles one, record the exception and the decision taken.

  2. Supply these accuracy arguments explicitly (REQUIRED): drift_tol, xtol of X.critical, tol of method="hill" / X.shell_floquet / nl.linear_gain / NewtonKrylovHookstep, tolerance of ContinuationSettings, tol of X.NewtonSolver, arnoldi_tol of X.equilibrium_eigenvalues (omitted: v0.1 default 1e-12 with a DeprecationWarning), safety of sim.cfl and of adaptive X.EmbeddedError. Write a value and say why; agent explain <name> lists them. Other accuracy defaults (for example the residual bound of cn.contour.beyn) are listed in the API reference of each call. Algorithm controls (trust radii, step growth, Krylov and iteration budgets, FD step) have declared defaults (cn.tolerances.explain()). Renamed arguments (nmodes/k → n_modes, X0 → x0, xatol → xtol, maxit → max_iterations, nsteps → steps, radius_ratio → eta, …) still work with a DeprecationWarning; write the new names. When the answer may not be the one you meant, Conatus emits a cn.errors.CorrectnessWarning (BaseStateWarning, GroupWarning, DefaultChoiceWarning). Python shows these by default, unlike a DeprecationWarning. Treat one as an error and declare the choice it names. Do not loosen a tolerance to make a refusal go away: find what is under-resolved.

  3. Under-resolved coefficients are refused (non-constant coefficient tail > cn.tolerances.NCC_TAIL_TOL): raise N, or declare ncc_cutoff= / ncc_tail_tol= explicitly. Never truncate in your code. Callable initial data are refused when aliased, not periodic on a periodic axis or not finite, and warn (cn.errors.InitialDataWarning) when only not fully resolved (a coarse N); initial(..., check=False) only if you mean it; a run warns once (cn.errors.UnderResolvedWarning) when its spectral tail exceeds RUN_TAIL_TOL, and an ill-posed implicit term (backward diffusion) warns at compile (cn.errors.IllPosedWarning): treat both as errors in your script.

  4. Check results three ways: the residual (res.residuals, sol.residual, E1.residual, rank_report()), convergence in N and dt (resolution_report(), cn.uncertainty), and an independent reference value when one exists. Report the value together with the checks you actually ran.

  5. Read explain() of every object you report (m, sim, res, lin, plan): a short summary by default (problem, scheme, checks, warnings); explain(full=True) states bases, tau placement, implicit/explicit split, dealiasing (default (p+1)/2 for the highest polynomial degree p, at least 3/2: declared), filters, residuals.

  6. run(until=T) must land on a whole number of steps (refused otherwise). dt stays fixed unless you build an adaptive controller. The CFL number limits the step for stability; it does not estimate the time error.

  7. Restarts are bit-for-bit only with identical numerics (scheme, dt, N, options) and the same problem (model, equations, parameters, box): a mismatch is refused with the diff; a deliberate change is sim.restart(path, allow=("kappa",)). Use sim.resume_or_start(dir, ...) (or cn.io.latest(dir) + sim.restart(...), which find .h5 and .npz) for multi-job runs; both .h5 and .npz restart bit for bit on CPU and GPU. Root searches raise when unconverged (allow_unconverged=True returns the flagged iterate); a Newton result with trivial=True is u = 0, not a new branch.

  8. Cost first: python -m conatus agent check run.py --memory and plan_memory before a GPU job; X.gpu_available() before backend="cuda". Small N on the CPU first, then scale. A second identical m.simulate(...) in the same process reuses the assembled operators (sim.explain() says “reused”; any change of parameters, N, dealiasing, equations, conditions or data rebuilds them).

  9. A solution found in a symmetry subspace is not declared stable until checked in the full space.

  10. Transposed matrix ≠ physical adjoint; use left=True, X.compare_adjoints, fm.vjp as documented.

  11. Experimental (shipped and tested; may change without a deprecation cycle): the Studio, the local hub, shells larger than 64 × 48 × 48, 3-D channel and pipe orbits (conatus.ecs.shooting.ShootingRPO, conatus.ecs.pipe.PipeTravellingWave). First use warns cn.errors.ExperimentalWarning; say so in what you report. X exports documented names only: anything else is conatus.<module>.<name> (X.<name> warns DeprecationWarning, gone in 0.3).
